# Configuration

All configuration is managed through two files in the agent's data directory. Most settings are automatic — the agent enrolls, receives its heartbeat interval from the server, and manages deployments dynamically.

---

## File Locations

| Platform | Data directory |
|----------|----------------|
| Linux | `/etc/ceagent/` |
| Windows | `C:\ProgramData\ceagent\` |

You can override the config file path with the `--config` flag on any command:

```bash
ceagent run --config /path/to/config.yml
ceagent status --config /path/to/config.yml
```

---

## config.yml

The agent's persistent configuration. Created automatically during enrollment.

```yaml
# /etc/ceagent/config.yml
server_url: "https://certkeeper.example.com:3000"

deployments:
  1:
    enabled: true
    post_deploy: "./scripts/deploy-nginx.sh"
  5:
    enabled: false
    post_deploy: "./scripts/deploy-mail.sh"
  12:
    enabled: true
```

### Options

| Key | Required | Description |
|-----|----------|-------------|
| `server_url` | Yes | CertKeeper server URL (e.g. `https://certkeeper.example.com:3000`). Set during enrollment. |
| `deployments` | No | Map of deployment ID → deployment config. Managed dynamically by the agent; user-customizable. |

### Deployment Config

Each entry under `deployments` is keyed by the deployment ID (integer) and supports:

| Key | Default | Description |
|-----|---------|-------------|
| `enabled` | `true` | Whether the agent should download and deploy this certificate. Set to `false` to opt out locally. |
| `post_deploy` | *(none)* | Script to run after writing new certificate files. See [Post-Deploy Scripts](post-deploy-scripts.md). |

**How deployments are managed:**

| Server says | Config has it? | Agent action |
|---|---|---|
| New deployment | No | Adds to config with `enabled: true`, no `post_deploy` |
| Existing deployment | Yes, enabled | Normal operation — downloads and deploys as needed |
| Existing deployment | Yes, disabled | Skips — user must manually re-enable |
| Deployment removed | Yes, enabled | Sets `enabled: false`, deletes cert files from disk |
| Deployment removed | Yes, disabled | No change |

The agent never deletes config entries — it only sets `enabled: false`. User-configured `post_deploy` scripts are always preserved.

### Script Paths

Both relative and absolute paths are supported for `post_deploy`:

- **Relative paths** (e.g. `./scripts/deploy-nginx.sh`) are resolved relative to the data directory (`/etc/ceagent/` on Linux, `C:\ProgramData\ceagent\` on Windows)
- **Absolute paths** (e.g. `/opt/scripts/deploy.sh`) are used as-is

## state.json

Runtime state that persists across restarts. **Do not edit this file manually** — it is managed entirely by the agent.

```json
{
  "config_version": 2,
  "heartbeat_interval": 180,
  "deployments_hash": "a1b2c3d4e5f67890",
  "deployment_hashes": {
    "1": "f6e5d4c3b2a19876",
    "12": "1a2b3c4d5e6f7890"
  }
}
```

| Key | Description |
|-----|-------------|
| `config_version` | Last acknowledged server config version. Sent in each heartbeat request. |
| `heartbeat_interval` | Current heartbeat interval in seconds (server-authoritative). Used as the initial timer on restart. Default: `180`. |
| `deployments_hash` | Hash of the server's deployment state. Used to detect changes without fetching the full deployment list on every heartbeat. |
| `deployment_hashes` | Per-deployment content hashes. Compared against the server's `content_hash` to detect certificate renewals. |

## Certificate Files

Created during enrollment. Used for mTLS authentication with the CertKeeper server.

| File | Permissions | Description |
|------|-------------|-------------|
| `client.crt` | `0644` | Agent mTLS certificate (signed by CertKeeper's internal CA) |
| `client.key` | `0600` | Agent private key (generated locally, never transmitted) |
| `ca.crt` | `0644` | CertKeeper CA certificate (used to verify the server's TLS certificate) |

On Windows, `client.key` ACLs are restricted to `SYSTEM` and `Administrators`.

These files are rotated automatically when the agent renews its certificate (when fewer than 15 days remain on the current cert, or when the server sends a `renew_agent_cert` action).

---

## Deployed Certificates

Certificate files for each deployment are stored under `deployments/<id>/`:

```
deployments/
├── 1/
│   ├── fullchain.pem   # Full chain (leaf + intermediates)
│   ├── cert.pem        # Leaf certificate only
│   └── privkey.pem     # Private key
└── 12/
    ├── fullchain.pem
    ├── cert.pem
    └── privkey.pem
```

| File | Permissions | Description |
|------|-------------|-------------|
| `fullchain.pem` | `0644` | Full certificate chain — used by most web servers |
| `cert.pem` | `0644` | Leaf certificate only |
| `privkey.pem` | `0600` | Private key |

On Windows, `privkey.pem` ACLs are restricted to `SYSTEM` and `Administrators`.

## Server-Authoritative Settings

The following settings are controlled by the CertKeeper server and cannot be overridden locally:

| Setting | Description |
|---------|-------------|
| **Heartbeat interval** | How often the agent checks in. Configured in the CertKeeper UI under Settings → Agents. The agent always uses the server-provided value. |
| **Agent cert lifetime** | Agent certificates are valid for 45 days. Renewal is triggered automatically when fewer than 15 days remain. |
| **Deployments** | Which certificates are assigned to this agent. Managed in the CertKeeper UI. The agent can only disable deployments locally — it cannot add or reassign them. |

## CLI Reference

| Command | Description |
|---------|-------------|
| `ceagent enroll --server <url> --token <cke_...>` | One-time enrollment |
| `ceagent run` | Start the daemon (foreground) |
| `ceagent run --config /path/to/config.yml` | Start with explicit config path |
| `ceagent status` | Show agent info, cert expiry, deployment count |
| `ceagent renew-cert` | Manually trigger agent cert renewal |
| `ceagent deployments` | List current deployments and their status |
| `ceagent deploy --id <id>` | Force re-download a specific deployment |
| `ceagent version` | Print version and build info |

### Global Flags

| Flag | Description |
|------|-------------|
| `--config <path>` | Override the config file path (default: `/etc/ceagent/config.yml` on Linux, `C:\ProgramData\ceagent\config.yml` on Windows) |
| `--verbose` | Enable debug logging |
